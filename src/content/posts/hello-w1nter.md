折腾了一段时间，这个完全由自己设计、打磨的静态博客终于上线了。作为这里的第一篇文章，我想聊聊这个博客项目本身——它诞生的缘由、审美与技术上的取舍，以及我对「个人博客」这件事的一点期待。

## 为什么要自己写一个博客

在这之前，我用过不少博客平台，也试过很多开源主题，但始终觉得差一点意思：要么界面花哨冗余，各种特效和模块喧宾夺主，让注意力离开了文字本身；要么定制化程度太低，很难完全贴合自己的审美与使用习惯。

我理想中的博客，应该是**内容优先**的：打开页面，文字就是绝对的主角，所有的设计都为阅读服务。于是干脆自己动手，基于 AstroPaper 二次开发，从零打磨一个只属于自己的空间——去掉一切不必要的装饰，只保留最纯粹的阅读体验。

## 设计审美：克制的极简主义

整个博客的视觉设计，围绕「干净、舒适、长久可读」三个关键词展开。

- **纯白底色 + Solarized 配色**：全站采用纯白背景，也不提供深色模式切换——并非技术上无法实现，而是我希望这个空间始终保持明亮、通透的质感。文字与强调色沿用了经典的 Solarized 配色，色调柔和不刺眼，长时间阅读也不易疲劳。
- **为中文优化的排版**：从字号、行高到段落间距，都针对中文阅读习惯反复调整，让文字有足够的「呼吸感」；代码块、引用、列表也做了统一的视觉处理。
- **恰到好处的细节**：导航栏保留了一只会待机、会行走的「小黑」作为小彩蛋；页脚会自动计算博客的运行天数——这个站点的起点定格在 2026 年 9 月 30 日。没有多余的动画，所有交互都点到为止。

同时我也做了很多「减法」：摄影、音乐、游戏、碎碎念这些泛生活模块都被移除了。这里不会是包罗万象的杂货铺，而是专注于思考与记录的自留地。

## 技术选型：轻量与工程化的平衡

博客基于 Astro 7 构建，在追求极致性能的同时，也兼顾了工程化的可维护性。

**核心框架：Astro + Tailwind CSS**

选择 Astro 的核心原因，是它「默认零 JS」的静态输出特性：构建后的页面几乎没有冗余脚本，加载速度快，天然对 SEO 友好。样式层使用 Tailwind CSS 4，搜索则交给 Pagefind——在构建时为全站生成静态索引，搜索完全在本地浏览器完成，不需要任何后端服务。文章 RSS、站点地图也都是标配。

**内容管理：Decap CMS**

为了不用每次写文章都改代码、提交 Git，我接入了 Decap CMS 作为可视化后台。通过 GitHub 登录即可写作，内容保存在独立的私有内容仓库中，与博客源码完全分离：

- 草稿与发布是两个独立步骤，稿件可以安心先存草稿；
- 发布时间可以设置为未来，到点由工作流定时检查、自动上线；
- 上传的图片会在同步时统一转换为最长边 1920px 的 WebP，并去除 EXIF 信息，兼顾加载速度与隐私。

正文编辑器支持可视化与 Markdown 两种模式，手机浏览器里也能随时写作。我自己固定使用 Markdown 模式——文字、图片、代码块都以纯文本形式存在，干净、可版本管理，也方便迁移。

**工程化与部署**

项目内置 ESLint 与 Prettier 统一代码风格，使用 Node.js 原生测试 runner 编写内容与构建测试，并提供 Docker 部署方案。发布链路由两个 GitHub 仓库分工：

- **源码仓库**：每次提交自动运行 lint、测试与构建，保证主干始终可用；
- **内容仓库**：文章发布触发生产环境的构建与部署，未来文章则由定时工作流处理。

写完即发布，同时每一次上线都经过完整的检查。

## 博客有哪些功能

虽然走极简路线，但核心的阅读与写作体验一个都没有缺席：

- **完整的内容体系**：文章列表与详情、标签分类、时间归档、全站搜索、RSS 订阅；
- **个人展示模块**：关于页面、旅行足迹地图（基于 d3-geo 绘制）、项目文档展示；
- **项目文档**：可以直接导入 README 或任意 Markdown 文件，为每个项目生成独立的站内详情页；
- **双语支持**：站点界面支持中 / 英文切换，文章正文则保留中文原文。

## 开源说明

项目已经完整开源在 GitHub：

👉 **[w1nterdec/my-blog](https://github.com/w1nterdec/my-blog)**

仓库结构清晰，便于二次开发：

```text
my-blog/
├── src/
│   ├── pages/        # 路由：首页、文章、标签、归档、搜索、关于、项目
│   ├── content/      # 本地 Markdown 内容（posts / projects / pages）
│   ├── components/   # 页面组件
│   ├── layouts/      # 布局
│   ├── styles/       # 主题色、排版与地图样式
│   ├── scripts/      # 小黑动画等前端脚本
│   ├── i18n/         # 中英文案
│   └── data/         # 足迹等站点数据
├── public/admin/     # Decap CMS 后台
├── server/admin/     # 后台 OAuth 服务
├── scripts/          # 内容同步、Pagefind 索引等构建脚本
├── infrastructure/   # 服务器部署配置
├── tests/            # 自动化测试
└── docs/             # 运维与个性化文档
```

如果你也想搭建一个类似的博客，可以直接参考或 Fork 这个仓库，README 里写了完整的本地运行、配置与部署教程。
